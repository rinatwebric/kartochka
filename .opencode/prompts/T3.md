# T3 — inspect + segment + compose + whitebg (ядро продукта)

Загрузи скилл test-driven-development для чистых функций.

Сделать в lib/pipeline/:
1. inspect.ts — размеры, соотношение сторон, резкость (дисперсия лапласиана через sharp),
   касание маски краёв кадра. Возвращает типизированный объект метрик.
2. segment.ts — маска товара через lib/models/sam.ts по промпту категории, сохранить mask.png
   рядом с исходником.
3. compose.ts — белый фон через lib/models/image.ts по маске; итоговый кадр по правилам площадки
   (по умолчанию 3:4, 900x1200); товар в кадре на 60-90%.
4. whitebg.ts — детерминированная доводка через sharp: альфа из маски с эрозией 1-2 px,
   всё вне альфы -> ровно (255,255,255); проверка «край товара не съеден» по доле изменённых
   пикселей внутри bbox; если съеден — откат к предыдущему кадру и флаг в результате.
5. runner.ts — оркестратор шагов: идемпотентность, запись статуса/времени/стоимости/ошибки
   в состояние джобы (state.ts), шаг можно вызвать повторно — перезаписывает результат.
6. types.ts — JobState, Metrics, ChecklistItem на zod (см. MASTER.md раздел 5).

Проверка обязательна: scripts/check-pipeline.ts берёт все файлы из fixtures/photos/ (если папка
пуста — сгенерируй 3 синтетических тестовых изображения товара через sharp и положи в
fixtures/photos/synthetic-*.jpg, это разрешено), прогоняет inspect->segment->compose->whitebg
и печатает по каждому файлу: размер, fill (доля bbox), bg_white (доля белых пикселей вне маски),
время, кредиты. В mock-режиме всё должно отработать без ключа.
