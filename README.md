# КАРТОЧКА

Фото товара с телефона — в готовую карточку для маркетплейса, которую площадка примет с первого раза. Белый фон 255,255,255, нужные пропорции, чек-лист регламента с числами и текст карточки — за один прогон.

Это не фотостудия. Photoroom и аналоги делают красивое фото — КАРТОЧКА делает валидатор регламента с числом: «пройдено 9 из 10, вот замер каждого пункта и что поправить». Красивое фото — побочный эффект, а не продукт.

## Как запустить локально

```bash
pnpm install
cp .env.example .env   # ключ можно не вписывать — будет MOCK-режим
pnpm dev                # http://localhost:3000
```

Проверки:

```bash
pnpm build              # обязано проходить без ошибок типов
pnpm evals --mock       # eval-стенд на фикстурах, без ключа и кредитов
pnpm check:pipeline     # сквозной прогон inspect→…→identity на synthetic-фото
pnpm check:rules        # движок регламента на трёх площадках + временная четвёртая
pnpm check:copy-export  # текст карточки и клиентская сборка ZIP
pnpm check:identity     # identity gate: same/substituted/петля ретраев
```

## MOCK-режим (демо без ключа)

Если `MODEL_API_KEY` пустой (или `MOCK=1`), все вызовы моделей идут через детерминированный `lib/mock/provider.ts`: правдоподобные задержки 300–800 мс, фиксированные боксы/вердикты, ошибок нет. Весь продукт — загрузка, студия, чек-лист, ZIP, батч, публичная страница — открывается и работает без сети и без кредитов. Проверка судейского сценария: стереть ключ, `MOCK=1`, открыть `/` → «Посмотреть готовый пример» → «Собрать карточку».

## Какая модель где и почему

| Шаг | Модель | Почему она |
|---|---|---|
| `segment` — маска товара | `sam-3.1` | сегментация по промпту категории; в MOCK — детерминированный бокс, дальше цепочка `sam-mask → sam-boxes → background-removal` на sharp |
| `compose` — кадр 3:4 | детерминированный коллаж на sharp (`modelUsed=false`) | генерация рвёт соответствие маски и кадра, а регламенту нужны считаемые пиксели; живая генерация подключается только с identity-петлёй (вариант B, см. `docs/DECISIONS.md`) |
| `identity` — тот ли товар | `muse-glimmer` (судья) + pHash + HSV + SSIM | независимый вердикт открытыми весами: 3 голоса большинством; формула `0.35·pHash + 0.25·HSV + 0.25·SSIM + 0.15·glimmer`, порог 0.90 |
| `rules` — текст/логотипы на фото | `muse-spark-1.3` строгим JSON `{ok,confident,bbox,reason}` | вердикты `no_text_on_main`, `no_watermark`, `single_object`; без уверенности — честный провал |
| `copy` — название, описание, характеристики | `muse-spark-1.3` | лимиты длины только из `rules/<mp>.json`, запрет корней «идеальн» |
| eval-стенд и черновики | `muse-spark-1.3-contributor` | дешёвый прогон 20 кейсов без траты основного бюджета |

Честные оговорки (проверено на этой машине, см. `docs/DECISIONS.md` T2):

- `muse-glimmer` — open-weight модель для self-host (vLLM/llama.cpp), через Model API не отдаётся; живой судья работает только с локальным рантаймом, в остальных режимах — MOCK.
- `sam-3.1` отдаёт не PNG-маску, а текст special-token с боксами; ветка `sam-mask` написана по документации и отработает при совпадении формата — первый живой прогон смотреть по полю `method` в отчёте.
- База и эндпоинты сверены с https://dev.meta.ai/docs: тексты — `POST /v1/responses {model, input}`, картинки — OpenAI-совместимые `POST /v1/images/generations|edits`.

## What was built during the hackathon

За пять дней с нуля: лендинг с загрузкой, 7-шаговый пайплайн (`inspect → segment → compose → whitebg → identity → rules → copy`) с идемпотентными шагами и 409-предусловиями, детерминированный white-bg fixer (эрозия 2px, всё вне маски — ровно 255,255,255, откат при повреждении края), identity gate с петлёй до 2 ретраев, движок регламента из JSON (новая площадка = новый файл), текст карточки с валидацией лимитов, клиентская сборка ZIP, батч на 20 фото с общим архивом, публичная read-only страница `/r/<id>`, реестр промптов v1/v2 с `promptIds` в отчётах, eval-стенд на 20 кейсов (JSON+CSV, `--compare v1 v2`), `/api/health` и `/api/stats`.

## Архитектура одной схемой

```
браузер                      Next.js (nodejs runtime)
  лендинг ──POST /api/jobs──▶ Map + /tmp/jobs/<id>/job.json
  студия ──POST /api/jobs/<id>/step {step}──▶ runStep: inspect…copy (по одному шагу
                                     на запрос — долгие генерации не упираются
                                     в таймауты Vercel; повтор шага перезаписывает)
  студия/батч ──GET /api/jobs/<id>/export + /asset/{main.jpg,mask.png,source}
              ──▶ ZIP собирается в браузере (jszip), сервер не участвует
  /r/<id> — публичная read-only страница результата, без авторизации
```

## Ограничения (честно)

- Состояние — память процесса + `/tmp/jobs`, без БД: рестарт сервера роняет демо-джобы. Осознанно: пять дней, одна демо-джоба, один инстанс.
- Регламенты `rules/*.json` — `verified: false`: числа-ориентиры, требуют сверки с официальными страницами (см. `docs/SOURCES.md`); в UI подпись с датой проверки.
- Порог identity 0.90 и формула — из `MASTER.md` §8, не подбирались «на глаз»; известная находка стенда: synthetic-3+wb даёт 0.887 при SSIM 0.987 (pHash плывёт на ресемплинге тонкой синтетики) — зафиксировано как fail-регрессия, порог не тронут.
- Живой `sam-3.1`/`muse-image-1.0` без ключа не проверялись — MOCK покрывает весь UI-путь, живой прогон смотреть по `method`/`modelUsed`.
